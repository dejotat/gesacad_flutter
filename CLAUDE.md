# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

GESACAD: Flutter app (Android + Web) for university academic management (Unicomfacauca). Three roles — Admin, Teacher, Student — talk to a separate Node.js/Express + MySQL backend (not in this repo). Code comments, UI strings and docs are in Spanish; match that. `README.md` has the use-case table (CU-01…CU-07), black-box test tables and DB schema.

## Commands

```bash
flutter pub get
flutter run -d chrome        # web
flutter run                  # Android emulator/device
flutter analyze              # lint (flutter_lints, see analysis_options.yaml)
flutter test                 # only test/widget_test.dart exists
flutter test test/widget_test.dart
```

Release APK on Windows: the Flutter SDK path contains spaces, so use the junction instead of plain `flutter build apk`:
`C:\flutter_sdk\bin\flutter.bat build apk --release` (output in `build\app\outputs\flutter-apk\app-release.apk`). `pubspec.yaml` pins `objective_c: 9.3.0` via `dependency_overrides` for the same space-in-path build bug — don't remove it.

## Backend URL

`lib/config/api_config.dart` holds `baseUrl` and every endpoint path. `baseUrl` defaults to Render (`gesacad-backend.onrender.com`) and is overridable **without editing code**: `flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:8081` (Android emulator: `http://10.0.2.2:8081`, LAN device: `http://192.168.X.X:8081`). The local backend lives in `Backend/` (`npm start`; `.env` points to local MySQL). Note: README still says Railway — the code is the source of truth. Never commit local-dev URLs.

## Architecture

- **Entry/session**: `main.dart` → `SplashScreen` pings the backend (`ApiService().ping()`, wakes the cold-start dyno), reads `userRol` from SharedPreferences and routes to `LoginScreen` / `AdminHome` / `TeacherHome` / `StudentHome`. There is no named-route table; navigation uses `utils/route_transitions.dart` helpers (`slideRoute`, …).
- **Services** (`lib/services`, no state-management package — plain singletons + `ValueNotifier`):
  - `ApiService` — singleton for all HTTP. 30s timeout; `_conRetry` retries GETs once (never use it on POST/PUT/DELETE — it would duplicate inserts). Two-level cache (in-memory 5-min TTL + SharedPreferences `apicache_*` to show last-session data); cache is invalidated on course/activity add/delete. URL path params must be wrapped in `Uri.encodeComponent` (backend crashes on `/ ? # %`).
  - `AuthService` — session in SharedPreferences (`userId`, `userName`, `userRol`) plus cached `profile_*` keys.
  - `AppSettings` (`settings_service.dart`) — theme/config via `ValueNotifier`s; `main.dart` rebuilds `MaterialApp` from `AppSettings.currentTheme`; themes live in `config/app_themes.dart` (dark mode = `AppThemeType.darkCarbon`).
  - `ChatbotService` (`chatbot_service.dart`) — el chat «Asistente GESACAD» (`widgets/chatbot_widget.dart`) habla con `POST /chatbot/ask` del backend, que llama a Google Gemini (ver «Asistente con Gemini (CU-15)»). El antiguo bot local de palabras clave se eliminó.
  - `tts_service.dart` / `talk_widget.dart` / `tts_button.dart` — text-to-speech accessibility (CU-07).
- **Platform split**: `utils/platform_utils.dart` with `_mobile` / `_web` variants (conditional imports) for web-vs-mobile behavior; `helpers/file_viewer_helper.dart` opens files with the direct Cloudinary URL (PDF/images directly, Office files through the Office Online viewer, zips as downloads). The server's `/files/proxy` endpoint is kept only for old app versions: the current app does not call it.
- **Login look**: `LoginScreen` (`screens/login_screen.dart`) is a thin wrapper that forces the dark brand theme (`AppThemes.of(AppThemeType.neon)`) whatever theme the user picked in Ajustes; the real UI is `_LoginView`. The background is `widgets/ui/cinematic_backdrop.dart` (`CinematicBackdrop`: verde azulado profundo (escena Neón) + additive aurora blobs turquesa/cian/lima + particles with constellation lines, 60 s seamless loop; static layers sit in their own `RepaintBoundary`; honours `MediaQuery.disableAnimations`; purely decorative: `ExcludeSemantics` + `IgnorePointer`). Keep it decorative and keep text contrast high. Tests: `test/login_backdrop_test.dart`.
- **Screens** are grouped by role (`admin/`, `teacher/`, `student/`) plus shared `calendar/`, `notifications/`, `profile/`, `auth/`.

## Backend contract gotchas

- Login is `POST /auth/login` `{username, password}` → `{token, user, …, response: 'LOGIN_SUCCESFULLY'}` (single L — server typo, keep it). The old `GET /users/:username/:password` still exists only as a fallback for servers without the new route and is switched off with `ALLOW_LEGACY_LOGIN=false`.
- Activity dates are stored in UTC; convert for display with `ActivityModel.toCol()` (Colombia, UTC-5).
- Submissions are limited to 5 MB and to pdf/doc/docx/png/jpg/jpeg/zip/xlsx/pptx — enforced in the app AND in the server (`addResource`: 413 `ARCHIVO_MUY_GRANDE`, 415 `TIPO_NO_PERMITIDO`). Teacher attachments: 10 MB, up to 5 files. Profile photo: image only, 5 MB. Limits are overridable with `MAX_SUBMISSION_MB`, `MAX_ATTACHMENT_MB`, `MAX_PHOTO_MB`.
- **Subida de archivos** (`server.js`): multer escribe a disco temporal (`os.tmpdir()/gesacad-uploads`, nombre aleatorio, nunca el del cliente) y se transmite a Cloudinary con `subirACloudinary(RUTA, …)`; `limpiarTemporales` (va ANTES de multer en cada ruta con archivos) borra el temporal al cerrar la respuesta, incluso en salidas anticipadas. Nunca volver a `memoryStorage`. El nombre original se guarda dentro de la URL con `::name::` y `|||`: pasa siempre por `nombreSeguro()`. Pruebas sin Cloudinary: `CLOUDINARY_FAKE=true` (ignorado si `NODE_ENV=production`).
- **Tipos de actividad**: `midterm` (Parcial), `quiz`, `project`, `resource` y `other`. `activities.type` es un ENUM de MySQL: `server.js` lo AMPLÍA al arrancar si falta `quiz` (aditivo, conserva los valores existentes). Al añadir otro tipo, ampliar también esa migración, `db/01-esquema.sql`, `utils/activity_type.dart` y los `_tipoLabel` del calendario y del detalle.
- **Nombres de archivo**: multer entrega `originalname` en latin1 («Póster» → «PÃ³ster»); `repararNombre()` (servidor) lo deshace y el id público de Cloudinary quita las tildes en vez de borrar la letra. La app repara los nombres ya guardados deformados (`FileViewerHelper.repararNombre`).
- **PDF/ZIP que no abren** (401 `x-cld-error: deny or ACL failure` en `res.cloudinary.com`): es el ajuste de seguridad de la cuenta de Cloudinary «PDF and ZIP files delivery». No se arregla con código (ni con `/files/proxy`, que recibe el mismo 401): la casilla «Allow delivery of PDF and ZIP files» debe estar MARCADA (sin marcar = bloqueado) en Cloudinary → Settings → Security, y guardar.
- Activity weightings (ponderado) per course must not exceed 100%; check via `ApiConfig.weightingMax` before creating.

## Modo sin conexión (offline)

- **Detección** (`services/connectivity_service.dart`): mide si el *backend* responde, no solo si hay wifi. `ApiService` informa cada éxito/fallo de red; sin conexión sondea `/health` cada 10 s. `isNetworkError(e)` distingue falla de red de error de aplicación.
- **Lectura**: `ApiService._getCached(key, uri)` guarda cada GET 200 en SharedPreferences (`apicache_*`) y, si no hay red, sirve la copia como un 200 sintético. Con `allowCache: false` (`fresh: true` en `getActivityContent`) exige dato del servidor. Solo para GET: nunca usar con POST/PUT/DELETE.
- **Escritura** (`services/offline_queue.dart`): `OfflineQueue` es un outbox persistente (entregas del estudiante y notas del docente). Envía en orden, se sincroniza sola al volver la conexión, reintenta con espera creciente en 5xx y marca `failed` en 4xx. Los archivos se guardan aparte (`outbox_file_store.dart`: disco en móvil, memoria en web — en web se pierden al recargar).
- **Anti-duplicados**: si un POST de entrega expira (`TimeoutException`) la operación queda `uncertain`; antes de reenviar se consulta `getActivityContent(fresh: true)`. Las notas son PATCH idempotentes y se reemplazan entre sí (gana la última).
- **UI**: `widgets/offline_banner.dart` (`OfflineShell` en el `builder` de `MaterialApp`) muestra el estado y el panel `CentroSync`. `utils/app_keys.dart` tiene las llaves globales de Navigator/ScaffoldMessenger.
- **Cerrar sesión** borra la cola y las copias (`AuthService.clearSession`); las pantallas piden confirmación si hay cambios sin enviar (`confirmarSalidaConPendientes`).
- Tests: `test/offline_test.dart`. Inyectar `OperationExecutor`, `OutboxFileStore` y `ConnectivityService.test(...)` para probar sin red.

## Arranque rápido y conexión en frío

- **El servidor de Render (plan gratis) duerme tras ~15 min sin uso y despertar tarda 30–60 s.** La app lo trata como caso normal, no como caída: `main()` lanza `ApiService().ping()` PRIMERO (corre en paralelo con el resto del arranque); `ping()` es `ConnectivityService.checkNow()`, una sola petición paciente (60 s) a `/health` que recibe la respuesta en cuanto el servidor despierta. Varias peticiones cortas abandonadas se la perderían hasta el siguiente sondeo.
- `ConnectivityService.espera` (usada por `ApiService._timeout`): **75 s** hasta ver responder al servidor una vez (o si está sin conexión), **30 s** después. `ConnectivityService.conectando` se activa si la PRIMERA conexión pasa de 2 s: el banner (`OfflineShell`) dice «Conectando con el servidor…» en vez de «Sin conexión». Nunca volver a un timeout fijo corto para el login o las lecturas.
- **Mantener el servidor despierto** (lo único que elimina el arranque en frío): un monitor externo que llame a `https://gesacad-backend.onrender.com/health` cada 5–10 min (UptimeRobot o cron-job.org, gratis). No está configurado desde el código.
- `main()` inicializa en paralelo (`Future.wait`: locale, ajustes, token); el push se inicia DESPUÉS de `runApp` y sin bloquear. El logo de `SplashScreen` espera lo justo (~1,1 s); antes eran 2,5 s fijos.
- **Poppins va incluida en la app** (`google_fonts/*.ttf` + `OFL.txt`, declarada en `pubspec.yaml`): `google_fonts` la usa desde los assets en vez de descargarla de internet (sin parpadeo de texto y sin red). Si se usa un peso/estilo nuevo, añadir su `.ttf` con el nombre `Poppins-<Peso>.ttf`. `robotoMono` (solo depuración) sí se descarga.
- La web se compila con `--no-web-resources-cdn` (CanvasKit lo sirve nuestro nginx, comprimido y en caché). `flutter run -d chrome` (modo depuración) es MUCHO más lento que la versión compilada: para medir rendimiento usar `--release` o la web de Docker.

## Desarrollo local (backend + app)

- **Un comando**: `.\tool\dev_local.ps1` (PowerShell) inicia MySQL, el backend (puerto **8081**, solo API) y la app en Chrome en el puerto **5000** apuntando al backend local. `-SoloBackend` para no abrir la app.
- **El puerto 8081 NO es la app**: solo responde datos (abrirlo en un navegador muestra una página que lo explica). La app se abre en `http://localhost:5000`.
- **Cada servidor tiene sus propios usuarios**: la base local (`Backend/.env` → MySQL local) no es la de producción. `npm run users` (en `Backend/`) lista los usuarios locales sin contraseñas. En depuración, la pantalla de login muestra un indicador de a qué servidor está conectada la app (`widgets/dev_server_badge.dart`).
- **Datos demo opcionales** para probar la evaluación docente (cursos con suficientes estudiantes): `npm run seed:dev -- --yes` en `Backend/` (solo corre contra MySQL local, idempotente, prefijo `demo_`, contraseña de desarrollo `Demo#2026`).
- **Migraciones al arrancar**: `server.js` agrega por sí solo las columnas que el código necesita y faltan en bases antiguas (perfil de `users`, `comment`/`teacherComment` de `resolutionsactivities`) y crea las tablas `evaluation_*`. Si una base antigua da 500 en entregas/actividades, reinicia el backend.

## Despliegue del backend (Render)

- El backend (`Backend/`, repositorio privado `dejotat/gesacad-backend`, rama `master`) se despliega **solo al hacer push a `master`**: Render ejecuta `npm install` y `npm start` (~45 s). No hay que tocar el panel de Render salvo para variables de entorno.
- **Verificar qué versión está en producción**: `GET https://gesacad-backend.onrender.com/health` devuelve `{status, version, uptimeSeconds}`; `version` es el commit corto desplegado (`RENDER_GIT_COMMIT`). Tras un push, esperar a que coincida con `git rev-parse --short=7 HEAD`.
- **Migraciones**: se aplican al arrancar y son idempotentes/aditivas (`CREATE TABLE IF NOT EXISTS`, `ALTER ... ADD COLUMN` ignorando `ER_DUP_FIELDNAME`). Nunca borran ni modifican datos. Antes de subir: `npm test` (28 pruebas contra una BD aparte).
- **Credenciales**: el `.env` NO se versiona (usa `Backend/.env.example` como plantilla; los valores reales viven en `.env` local y en Environment de Render). El `.gitignore` del backend debe quedar en UTF-8 (en UTF-16 git lo ignora en silencio).
- **Conexiones a MySQL**: `server.js` usa un **pool** (`DB_POOL_SIZE`, por defecto 2, tope 10; se abren bajo demanda; el arranque REINTENTA la conexión cada 5 s y ninguna petición espera la migración más de 15 s: sin esto un despliegue con el servidor anterior vivo dejaba el login colgado) y el módulo de evaluación otro de 2. Antes era UNA conexión: si la base en la nube la cerraba por inactividad el servidor quedaba roto hasta reiniciarlo, y las transacciones de varios usuarios se mezclaban. Las transacciones (`ejecutarTransaccion`) usan una conexión propia y su `q` es la ÚNICA forma válida de consultar dentro de ellas. Las migraciones de arranque van encadenadas en orden. Las bases en la nube limitan las conexiones simultáneas: si el plan es pequeño, baja `DB_POOL_SIZE` antes de subirlo. Render envía SIGTERM al redesplegar: el servidor cierra ordenadamente.
- **Integración continua**: `.github/workflows/pruebas.yml` en cada repositorio. Backend: MySQL 8 de servicio + `npm ci` + `npm test`. App: Flutter 3.41.2 + `flutter analyze` (solo errores rompen) + `flutter test`. Render despliega al hacer push sin esperar las pruebas: mira la pestaña Actions del repositorio después de cada push.

## Seguridad: contraseñas, sesiones y permisos

- **Contraseñas**: se guardan con **scrypt** (`Backend/auth.js`, sin dependencias) en `users.pass_hash`; nunca se devuelven por la API. Al arrancar, el servidor agrega las columnas `pass_hash`/`token_version` y cifra en segundo plano las contraseñas antiguas; **el texto plano de `users.pass` se conserva** hasta el paso explícito de purga (`npm run purge:plain -- --yes`, o `PURGE_PLAINTEXT=true` una vez en Render) para poder volver atrás. Contraseñas nuevas/cambiadas: 8–64 caracteres con mayúscula, minúscula, número, símbolo y sin el usuario (validado también en el servidor).
- **Sesiones**: token JWT HS256 (7 días, `JWT_TTL_HOURS`) en `Authorization: Bearer`. Lleva la versión de sesión del usuario (`tv`): cambiar contraseña/rol, eliminar al usuario o `POST /auth/logout-all` revocan los tokens. `POST /auth/refresh` lo renueva (la app lo hace al abrir/volver si pasaron >12 h). `JWT_SECRET` (≥16 caracteres) en el entorno; si falta se deriva de las credenciales de la BD y se avisa.
- **Permisos por ruta** (`auth.acceso(...)` en `server.js`): Admin gestiona usuarios/cursos; el docente solo sus cursos y actividades; el estudiante solo lo suyo; notificaciones y detalle de actividad usan el rol **de la sesión**, no el de la URL. `/files/proxy` es público a propósito (solo reenvía `https://res.cloudinary.com`, validando el host real).
- **`AUTH_MODE`**: `enforce` (defecto desde el 2026-10-21) bloquea con 401/403; un valor mal escrito también cae en `enforce`. `monitor` NO bloquea y registra en consola `[auth:monitor] bloquearía …`; `off` solo para emergencias. **Volver atrás sin redesplegar**: en Render → Environment → `AUTH_MODE=monitor` (reinicia solo, ~1 min) y se avisa en el registro de arranque. `ALLOW_LEGACY_LOGIN` ahora es `false` por defecto (el login antiguo con la contraseña en la URL responde 410 `UPDATE_REQUIRED`); `true` lo reactiva. Pendiente del plan: definir `JWT_SECRET` en Render y purgar el texto plano (`PURGE_PLAINTEXT=true` una sola vez, irreversible).
- **Fuerza bruta**: 8 fallos por usuario+IP y 60 por IP cada 15 min → 429 con `Retry-After`.
- **App**: `services/auth_client.dart` (`AuthClient`) se instala en `main()` con `http.runWithClient` y añade el token **solo** al origen de `ApiConfig.baseUrl`; ante un 401 de sesión (`TOKEN_EXPIRADO/INVALIDO`, `SESION_REVOCADA`) `SessionGuard` descarta el token (sin borrar datos ni cambios pendientes sin conexión) y lleva al login con el motivo. `AuthService` guarda el token (`authToken`); una sesión abierta contra un servidor antiguo sin tokens se marca `legacySession`. Los errores de gestión de usuarios llegan como `ApiMessageException` con el texto del servidor.
- **Tests**: `npm test` en `Backend/` (92: unitarias de auth, integración con el servidor real en una BD aparte —matriz de permisos, migración, revocación—, purga y evaluación); `test/auth_client_test.dart` en la app.

## Evaluación docente (CU-08)

- **Flujo**: el Admin crea un periodo (borrador) con su instrumento y ventana de fechas, lo publica (se congela y se toma la "foto" de curso+docente) y lo cierra; el estudiante evalúa a cada docente de sus cursos matriculados una sola vez; los resultados (Admin y docente) existen **solo con el periodo cerrado**.
- **Backend** (repo aparte en `Backend/`, módulo `evaluations.js`, rutas `/evaluations/*`, tablas `evaluation_*` creadas al arrancar con `CREATE TABLE IF NOT EXISTS`; `npm test` usa una BD aparte `bdgesacad_test`). Reglas: anonimato (participación y respuestas en tablas sin vínculo; sin hora ni id en las respuestas), una respuesta por estudiante/curso (PK), **participantes elegidos por el Admin** (`evaluation_scope`: docente → curso → estudiantes; `scope_mode` all/custom; solo los habilitados pueden responder; selección congelada al publicar), mínimo de respuestas (3–50, def. 5) para mostrar resultados, nada de promedios parciales. **Identidad**: con `AUTH_MODE=enforce` sale de la sesión (token) y el `adminId/studentId/teacherId` del cliente solo se contrasta (403 `IDENTIDAD_NO_COINCIDE` si no coincide).

## Notificaciones push (CU-13)

- **Qué hace**: cada notificación NUEVA de la bandeja (CU-11) también llega al teléfono con la app cerrada, por Firebase Cloud Messaging (API HTTP v1). Todo lo demás funciona igual sin push: si falta la configuración, la bandeja sigue.

## Docker (despliegue local y entrega)

- **Qué hay**: `compose.yaml` (raíz; Compose lo prefiere a `docker-compose.yml`, **no crear ese otro archivo**) levanta tres contenedores: `db` (MySQL 8.4), `backend` (`Backend/Dockerfile`, Node 22 en dos etapas, usuario `node`, `HEALTHCHECK` a `/health`) y `web` (`Dockerfile` de la raíz: Flutter compilado + `nginx-unprivileged` en el 8080, publicado en `127.0.0.1:5000`). La API sale en `127.0.0.1:8081`. Los puertos solo escuchan en localhost.
- **Arranque**: `.\docker\iniciar.ps1` (o `./docker/iniciar.sh`) crea `.env` con contraseñas ALEATORIAS desde `.env.docker.example` (nunca pisa un `.env` existente), construye y arranca con `--wait`, y muestra la contraseña del admin una sola vez. `-SoloGenerar` solo crea el `.env`. **`-WebLocal`** compila la web en el equipo (`flutter build web`) y usa el objetivo `web-local` del `Dockerfile` (`WEB_TARGET` en compose): evita descargar la imagen de Flutter (varios GB; con internet lento tarda horas). Sin él se compila dentro de Docker (objetivo `produccion`, el reproducible).
- **Base de datos**: nace VACÍA. MySQL ejecuta solo `Backend/db/01-esquema.sql` (5 tablas base, sin datos ni cuentas; reproduce la estructura real) la primera vez que se crea el volumen; el resto de tablas (17 en total) las crea el servidor al arrancar. El primer administrador sale de `ADMIN_BOOTSTRAP_USER`/`ADMIN_BOOTSTRAP_PASSWORD` (`crearAdminInicial` en `server.js`): solo se crea si NO existe ningún Admin, la contraseña pasa la misma política que cualquier otra y se guarda solo cifrada. `docker compose down` conserva los datos; `down -v` los borra.
- **Variables**: `DB_USER`, `DB_PASS`, `MYSQL_ROOT_PASSWORD`, `JWT_SECRET` (obligatorias), `ADMIN_BOOTSTRAP_*`, `CLOUDINARY_*` y `FIREBASE_SERVICE_ACCOUNT` (opcionales), `API_BASE_URL` (dirección de la API para el NAVEGADOR; se graba al compilar la web: si cambia, `docker compose up -d --build web`). `NODE_ENV=production` dentro de la imagen: `CLOUDINARY_FAKE` se ignora, así que sin credenciales de Cloudinary todo funciona menos subir archivos.
- **Trampas conocidas**: (1) en nginx un `add_header` dentro de un `location` descarta los del nivel superior: las cabeceras de seguridad van en `docker/security-headers.inc` y se incluyen en cada `location`. (2) `.env` debe guardarse en UTF-8 SIN BOM (con BOM Docker lee mal la primera variable); `iniciar.ps1` ya lo hace, pero el propio script lleva BOM para PowerShell 5.1. (3) En PowerShell `"$archivo: texto"` falla (`$archivo:` se toma por unidad): usar `${archivo}`. (4) Los `.dockerignore` excluyen `*.sql`, `.env*`, `firebase/`, pruebas y `Backend` (en la web): no meter datos ni secretos en las imágenes.
- **Puertos**: la app es `http://localhost:5000`; el 8081 es SOLO la API. Con `APP_URL` (compose lo fija en `http://localhost:5000`) `GET /` redirige (302) a la app cuando lo pide un navegador (`Accept: text/html`); apps, monitores y el HEALTHCHECK siguen recibiendo JSON 200. Solo se acepta http(s). Sin `APP_URL` (Render, desarrollo local) se muestra la página informativa. `iniciar.ps1`/`.sh` abren la app al terminar (`-NoAbrir`/`--no-abrir` lo evita).
- **Base desde el equipo**: `db` publica `127.0.0.1:${DB_HOST_PORT:-3307}` (NO 3306: en este equipo ya hay un MySQL local en ese puerto). `docker/datos-demo.ps1` ejecuta `Backend/scripts/seed_dev.js` contra ese puerto (cuentas `demo_*`; con la columna `pass_hash` guarda solo el hash). `docker/respaldo.ps1` hace mysqldump/restauración DENTRO del contenedor (no usar `>` de PowerShell 5.1: reescribe en UTF-16); `respaldos/` está en `.gitignore` y `.dockerignore`.
- **Migrar desde la nube**: `docker/migrar-desde-nube.ps1` = mysqldump de solo lectura (contenedor `mysql:8.4` aparte, contraseña por variable de entorno, nunca en la línea de comandos) → respaldo previo de Docker → restauración con confirmación → conteo de filas → reinicio de la API. Los datos de conexión pueden ir en `.env.nube` (plantilla `.env.nube.example`, ignorado por git) para no escribirlos ni pegarlos en un chat. `-BaseDestino` restaura en otra base (pruebas). Trampas de PowerShell 5.1 al llamar a `docker`: se pierden las comillas dobles internas, `2>&1` convierte el progreso de `docker compose cp` en error y una tubería a `sh` antepone un BOM; por eso los comandos van en `sh -c` sin comillas dobles. Probado contra una base temporal; NO contra Clever Cloud real.
- **SEGURIDAD (pendiente)**: `gesacad_db4free.sql` y `bdgesacad.sql.sql` se retiraron del árbol de trabajo (limpieza de 2026-11-06; copia local en `respaldos/sql-historicos/`, ignorada por git), pero **siguen en el HISTORIAL** de un repositorio PÚBLICO con cuentas de contraseña en texto plano y datos personales. Pendiente de quien administra el repositorio: cambiar esas contraseñas en todos los entornos, y hacer el repositorio privado o purgar el historial (reescribirlo exige force-push). No usarlos en Docker ni cargarlos en ningún entorno.

Reglas aprendidas (cada una era un fallo real, hay prueba): (1) los botones de solo ícono se nombran con `tooltip`, que NO viaja en `label`: leerlo aparte (`SemanticsData.tooltip`); (2) se recorren los nodos de arriba abajo y se lee el primero que tenga algo que decir (un globo de ayuda o un telón sin texto no debe tapar lo de debajo); (3) al arrancar con el lector ya activo NO se habla (el navegador bloquea la voz sin gesto del usuario); (4) en Flutter ≥ 3.32 los flags son `flagsCollection` (`Tristate`/`CheckedState` de `dart:ui`), no `hasFlag`; (5) NO decir «botón» ni «encabezado» al final de cada frase (el usuario lo rechazó por repetitivo); `IndicadorLectorVoz` es solo visual (`ExcludeSemantics`: el lector lo leía cada vez que se volvía a una pantalla): solo se dice el rol cuando aporta (control deslizante, enlace) y los estados; tampoco «campo de texto» ni el prefijo «Pantalla:» al cambiar de pantalla (solo el título). Los números sueltos llevan su contexto («Código de la materia 4832»). Al entrar al panel de un rol, cada `*Home` llama a `ScreenReader.bienvenida(rol)` («Bienvenido al panel de docente»), que sustituye al anuncio de pantalla de esa transición. **Voz**: `utils/voice_picker.dart` puntúa las voces del sistema y elige una masculina en español, con preferencia por las «Natural» de Edge (Gonzalo, Álvaro, Jorge); tono grave y ritmo pausado en web (`platform_utils_web.dart`) y Android (`platform_utils_mobile.dart`). Depende de las voces instaladas en el equipo. Prueba: `test/voice_picker_test.dart`. Pruebas: `test/screen_reader_test.dart`.

**Reglas para todo widget nuevo (CU-07)**: ícono sin texto → `tooltip`/`Semantics(label)`; imagen decorativa → `ExcludeSemantics`; área táctil ≥ 48×48 (`AnimatedIconButton` ya dibuja 44 pero toca 48); errores con `liveRegion: true`; un título de pantalla (AppBar o `Semantics(namesRoute)`); el texto de una tarjeta tocable va en su etiqueta (incluido el cuerpo, no solo el título). Se comprueba con las guías oficiales `labeledTapTargetGuideline` y `androidTapTargetGuideline` en `test/accesibilidad_test.dart` (login, recuperar contraseña, invitado, calendario, tarjeta de curso, menú de cuenta, avisos de conexión y notificaciones) y `test/accesibilidad_paneles_test.dart` (los tres dashboards): al añadir una pantalla pumpeable, añadirla ahí.

Original requirements:
